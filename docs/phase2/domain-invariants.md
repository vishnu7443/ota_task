# Domain Invariants Catalogue

Domain invariants are conditions that must **always** remain true across every transaction, regardless of UI client, retry, or concurrency.

| Invariant ID | Formal Condition (Must Always Hold) | Enforcing Module | Enforcement Operation(s) | Violation Behavior |
| --- | --- | --- | --- | --- |
| **`INV-STK-01`** | **Non-Negative Stock:** `InventoryBalance.on_hand_qty_base >= 0` for every Raw Material, Packaging Material, and Finished Product. | `Inventory` | `PostProductionIssues`, `PostProductionOutput` (packaging), `PostDispatchDeduction`, `PostStockAdjustment` | Abort transaction; return `409 Conflict` with exact available vs requested shortage. |
| **`INV-STK-02`** | **Reservation Cap:** `0 <= InventoryBalance.reserved_qty_base <= InventoryBalance.on_hand_qty_base` *(unless physical adjustment forced under Admin override)*. | `Inventory` & `Orders` | `ReserveFinishedStock` (Order Approval), `PostDispatchDeduction` | Block concurrent approvals exceeding `Available = On-Hand - Reserved`. |
| **`INV-STK-03`** | **Ledger Closure Invariant:** `InventoryBalance.on_hand_qty_base == SUM(InventoryMovement.signed_qty_base)` for every item. | `Inventory` | All stock-mutating methods + `ReconcileBalancesFromLedger` | Reject out-of-band balance updates; only `Inventory` mutates balance alongside ledger insert. |
| **`INV-STK-04`** | **Mandatory Source Traceability:** Every `InventoryMovement` has non-null `(source_doc_type, source_doc_id)` pointing to an existing document (`PUR`, `PRD`, `DSP`, `CN`, `ADJ`, `OPENING`). | `Inventory` | `AppendMovement` | Reject movement creation missing valid source reference. |
| **`INV-STK-05`** | **Cost-Lot Conservation:** For every `CostLot`, `0 <= remaining_qty_base <= original_qty_base` and `SUM(depleted_qty) == consumed_movement_qty`. | `Inventory` | `ConsumeCostLots` (FIFO / WAvg), `CreateCostLot` | Rollback transaction if lot depletion mismatches issued qty. |
| **`INV-ORD-01`** | **Submission Idempotency:** At most one `SalesOrder` exists per `(salesman_id, client_order_id)`. | `Orders` | `SubmitOrder` | Return existing order cleanly without inserting duplicate order/lines. |
| **`INV-ORD-02`** | **Dispatch Bounded by Approved/Invoiced Qty:** `SUM(DispatchItem.dispatched_qty_pkts) <= InvoiceItem.qty_pkts <= SalesOrderItem.approved_qty_pkts`. | `Billing` | `RecordDispatch`, `IssueInvoiceFromOrder` | Reject over-dispatch or over-invoicing with `422 / 409`. |
| **`INV-BIL-01`** | **Posted Invoice Immutability:** Any `Invoice` with `doc_status != DRAFT` cannot be hard-deleted or have line prices/quantities/taxes mutated. | `Billing` | `DeleteInvoice`, `UpdateInvoice` | Reject mutation (`409 Conflict`); direct Admin to `IssueCreditNote`. |
| **`INV-BIL-02`** | **Gap-Free FY Sequential Numbering:** `Invoice.invoice_number` and `CreditNote.cn_number` are unique per `(doc_type, financial_year)` and assigned only upon `ISSUED` transition. | `Billing` | `IssueInvoiceFromOrder`, `IssueCreditNote` | Lock `FiscalSequence` row; rollback sequence increment if posting fails. |
| **`INV-BIL-03`** | **GST Place-of-Supply Exclusivity:** If `INTRA_STATE`, `igst_total_paisa == 0` and `cgst_total_paisa == sgst_total_paisa`; if `INTER_STATE`, `cgst_total_paisa == 0` and `sgst_total_paisa == 0`. | `Billing` | `ComputeInvoiceTaxes`, `ComputeCreditNoteTaxes` | Assert tax symmetry prior to persisting invoice. |
| **`INV-PAY-01`** | **Payment Allocation Cap:** `SUM(PaymentAllocation.allocated_paisa for payment) <= Payment.amount_paisa`, and `SUM(PaymentAllocation + CreditNotes for invoice) <= Invoice.grand_total_paisa`. | `Payments` | `RecordAndAllocatePayment`, `AllocateAdvance` | Reject over-allocation unless excess stays unallocated advance on customer account. |
| **`INV-PAY-02`** | **Receivable Integrity:** `CustomerReceivable.outstanding_paisa == original_paisa - credited_paisa - paid_paisa >= 0`. | `Payments` | `CreateReceivable`, `AdjustReceivableFromCN`, `RecordPayment` | Rollback transaction if AR drops negative (unless converted to advance credit). |
| **`INV-PRD-01`** | **UOM Dimension Compatibility:** Material quantities entered in any document must belong to `Material.unit_dimension` (`MASS`, `VOLUME`, or `COUNT`). | `ProductionAndBom` & `Purchasing` | `ConvertToCanonicalUnit`, `CreateBomVersion`, `RecordPurchaseReceipt`, `StartProductionRun` | Reject `400 Bad Request` on dimension mismatch (`e.g., Flour in Litres`). |
| **`INV-PRD-02`** | **BOM Version Immutability:** A `BomVersion` pinned by `>= 1` `ProductionRun` cannot be edited or deleted; updates create `version_no + 1`. | `ProductionAndBom` | `UpdateBom` | Auto-clone into new `BomVersion`; block in-place edit. |
| **`INV-PRD-03`** | **Costing Completeness & Non-Zero Yield Divisor:** `ProductionCostSummary` cannot divide by zero (`actual_good_output_qty > 0` for packet unit cost; `0`-output scrapped runs mark `cost_per_packet = N/A` and expense total loss). | `Costing` | `ComputeRunCostSummary` | Guard division; treat failed `0`-packet batch as total scrap loss (`EC-06`). |
| **`INV-FIN-01`** | **Exact Paisa Arithmetic:** Zero IEEE-754 floating-point types anywhere in money, tax, cost, or margin calculations. | `Billing`, `Payments`, `Purchasing`, `Costing` | All financial domain services | Enforce integer paise (`MoneyPaisa`) / exact `Decimal` with `ROUND_HALF_UP`. |
| **`INV-SEC-01`** | **RBAC & Read-Only Auditor Guarantee:** `ACCOUNTANT_AUDITOR` never passes any write endpoint; `SALESMAN` never accesses another salesman's records or factory raw/cost data. | `IAM` + All Modules | Request authorization guard on every command | Reject with `403 Forbidden` and write security event to `AuditLog`. |
| **`INV-AUD-01`** | **Immutable Audit Trail:** `AuditLog` entries are strictly append-only; no user (including `OWNER`) can update or delete `AuditLog`. | `ReportingAndAudit` | All edit/approval/cancel/adjustment commands | Write `AuditLog` in same transaction as mutation; forbid update/delete operations. |
