# Phase 5 Known Limitations & Scope Boundaries

1. **Billing, Dispatch & Payments Explicitly Deferred:** Per Phase 5 boundaries, `APPROVED` orders reserve finished goods in `inventory.stock_reservations` / `inventory.inventory_balances` without generating GST tax invoices, recording physical dispatches (`DISPATCH_OUT`), or collecting customer payments yet. `OrderStatus.INVOICED`, `PARTIALLY_DISPATCHED`, and `DISPATCHED` transitions will unlock in the next phase.
2. **Production Runs & Costing Deferred:** Production material issues (`RAW_MATERIAL` / `PACKAGING_MATERIAL`), output receipts (`PROD_OUTPUT_IN`), consumption/yield variances, and packet costing belong to the Production phase. Until then, sufficient-stock approval verification in tests/dev uses controlled opening/test stock fixtures ([dev_fixtures.py](file:///d:/mac/ota/backend/app/seeds/dev_fixtures.py)) rather than fabricating fake production runs.
3. **Price Override Role Scope:** Currently only `FACTORY_ADMIN` can modify unit prices directly on pre-approval sales orders (`403` for all other roles, with mandatory reason and immutable `original_unit_price_paisa` preserved). Price list master CRUD UI (`sales.price_lists`) remains managed via seed/migrations.
4. **Polling Synchronization vs Push Transport:** Both Admin (`10s` / `15s`) and Salesman (`10s` + focus refresh) synchronize state cleanly via REST polling. WebSockets/SSE are deferred as unnecessary for small-factory concurrency.
5. **Pre-Approval Edit Lock Policy:** Once an order reaches `APPROVED` and stock is reserved, quantities and unit prices are locked (`409 ORDER_LOCKED`). Changing committed quantities requires cancelling (`APPROVED -> CANCELLED`, which releases active reservations) and placing a revised order.
