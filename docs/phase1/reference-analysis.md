## 2. Independent Engineering Insights (Interview & Evaluation Readiness)

1. **Why Separating Bulk Recipe BOM from Packaging BOM Matters (Section 9 Live Interview Prep):**
   Notice Section 9 explicitly warns shortlisted candidates:
   > *"a small change made on the spot (for example, 'add a second pack size of 500 g sharing the same BOM')."*
   In `Murukku 200 g`, `200 expected packets × 200 g = 40,000 g (40 kg)` net finished murukku per batch (matching `40 kg` flour input!). If we design our conceptual BOM so a **Bulk Base Recipe** (`Murukku Base`: `40 kg` flour, `10 L` oil, `1.2 kg` spice -> `40 kg` bulk output) links to pack-size **SKU Packaging Rules** (`Murukku 200 g`: `200 g` bulk + `1` `200g pouch` + `1/20` `carton`; `Murukku 500 g`: `500 g` bulk + `1` `500g pouch` + `1/N` `carton`), then:
   - Adding `Murukku 500 g` takes **zero code rewrites** and shares the exact cooking BOM (`80` expected packets per `40 kg` batch), while keeping benchmark `Murukku 200 g` calculations 100% identical!
   - Even if we keep a unified BOM UI for simplicity, ensuring the underlying model separates **cooking/bulk inputs per batch weight** from **per-packet packaging inputs** makes the live interview modification effortless.

2. **Alignment with Global Engineering Principles (`Python`, Deterministic & Explainable Logic):**
   - Choosing **Python** for the backend domain & calculation engine provides native `decimal.Decimal` / arbitrary-precision integer-paisa arithmetic, deterministic rule evaluation (stock reservation, GST place-of-supply routing, FIFO lot depletion, variance flagging), clean automated testing (`pytest`), and reliable CSV/Excel/PDF generation.
   - Making every automated decision (stock shortage calculation, GST tax split, FIFO cost layer depletion, variance tolerance alert) **deterministic, explainable, and visibly logged** matches both the NIT Trichy auditability mandate and high-reliability operational design standards.
